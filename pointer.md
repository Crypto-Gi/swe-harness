# Engineering skills (swe-harness)
- Any change to code in a repository: follow the swe-change skill.
- Only when the user explicitly asks for a review, a second opinion or a check before merge: use the swe-review skill. Never start a review on your own.
- A bug that survives one fix attempt: swe-debug. A code repository with no agent-guide.md: offer swe-bootstrap.
